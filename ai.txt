Recommended Offline AI Architecture
1️⃣ ONE Primary Model (Keep It Simple)

Use only ONE local LLM

✅ Best choice

Phi-3.5-mini-instruct (Q4_K_M)

Why:

Fastest reasoning per watt

Excellent financial logic

Stable answers

Smaller memory footprint

Easier battery management

👉 Multilingual?
Handle that outside the LLM (see below).

2️⃣ Multilingual Support (WITHOUT LLM multilingual load)

Instead of a multilingual LLM (heavy), do this:

🔹 Language Detection (tiny)

fastText lid.176.bin

Runs in milliseconds

<1MB RAM

🔹 Translation (optional)

Use ML Kit on-device translation

Fully offline

Supported by Google

No GPU stress

👉 Flow:

User language → Translate to English → Phi → Translate back


This keeps the AI:

Smaller

Faster

Safer

3️⃣ Financial “Learner” (Not an LLM)

Your idea is correct:

The chatbot should refer to a learner model, not learn itself.

🎯 Learner model purpose

Learn spending habits

Predict bills

Detect anomalies

Provide structured facts to the chat

✅ Best learner type (on-device)
Task	Model
Spending clusters	MiniBatch K-Means
Bill prediction	TFT-lite or LSTM
Anomalies	Isolation Forest
Seasonality	Holt-Winters
Risk score	Logistic regression

All converted to TFLite INT8.

💡 The LLM never sees raw data — only summaries.

4️⃣ Memory System (Very Important)
🧠 Memory Layers

DO NOT store full chat history

Layer 1 – User Financial State (Structured)
{
  "monthly_income": 3200,
  "avg_spend": 2800,
  "rent": 900,
  "next_bill": {
    "name": "Electricity",
    "amount": 120,
    "due_in_days": 5
  },
  "risk_level": "low"
}

Layer 2 – Preferences
{
  "tone": "friendly",
  "detail_level": "short",
  "language": "sw"
}

Layer 3 – Short-term Chat Memory (last 3–5 turns)
5️⃣ How Chat Should Work (UX Flow)
User asks:

“Will I struggle to pay rent next month?”

Your system:

Query learner models

Build a clean prompt

Ask Phi only once

User income: $3200
Rent: $900
Predicted expenses: $2100
Savings trend: stable

Answer kindly and briefly.

LLM output:

“You should be fine next month. After rent, you’ll still have about $200 buffer. Want tips to grow it?”

✨ Friendly
✨ Accurate
✨ Fast
✨ Calm

6️⃣ Compose UI (Friendly by Default)
Design rules:

No walls of text

Max 3 bullets

Emojis sparingly (1–2 max)

Use “suggested questions” chips

Example:

AssistChip("Can I afford this?")
AssistChip("Predict my bills")
AssistChip("How can I save?")

7️⃣ Offline Safety & Trust
Show clearly:

🔒 “Runs 100% on your device”

📴 “No internet required”

🧠 “Your data never leaves your phone”

This builds massive trust.

8️⃣ Battery & Thermal Strategy (Critical)
Rules:

Load LLM on demand

Unload after response

Cap context to 1–2 KB

Use CPU only (no GPU lock)

Disable background inference

Thermal wins:

Phi-3.5 Q4 < 2 seconds

Learners run once per day

No continuous listening

9️⃣ When NOT to Use AI

Important for friendliness:

❌ Don’t use LLM for:

Simple math

Static rules

Warnings

Use plain Kotlin logic instead.

🏆 Final Recommendation Summary
Component	Choice
LLM	Phi-3.5-mini-instruct Q4
Multilingual	fastText + ML Kit
Learner	TFLite models
Memory	Structured + short
UI	Compose + chips
Network	None
Privacy	On-device only
